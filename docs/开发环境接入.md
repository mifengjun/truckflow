复制仓库 `.env.example` 为 `.env.local`，通过本地编辑器或平台 Secret 配置值。实际环境文件已被 Git 忽略；不要把密钥贴进聊天或提交。

| 变量 | 获取 / 作用 |
| --- | --- |
| `APP_ORIGIN` | 本地 `http://127.0.0.1:3000`；预览部署使用该预览实际 Origin |
| `NEXT_PUBLIC_SUPABASE_URL` | 项目的 Auth/API URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable Key，不授予业务表匿名访问 |
| `SUPABASE_SECRET_KEY` | 服务端 Auth 管理用途，邀请账号时使用；不得放在客户端 |
| `DATABASE_URL` | 受限运行数据库账号的连接；已建立独立 `truckflow_runtime` 角色，使用 Session pooler |
| `MIGRATION_DATABASE_URL` | 单独迁移连接，管理 schema；运行时不得使用 |

依据：[Supabase SSR 官方说明](https://supabase.com/docs/guides/auth/server-side/creating-a-client?framework=nextjs)。正式接入代码提供配置校验，不会在缺配置时模拟成功。

## 2 身份和数据库

- Auth 使用邮箱密码；客户账号由管理员邀请，正式项目关闭公开注册入口并核对 Auth 服务本身的注册设置。
- 配置本地/测试站点允许的邀请与密码恢复回调 URL，拒绝任意外部跳转。测试邮件与生产邮件配置分开；发送真实邀请属于实际运营动作，验收先用自有测试邮箱。
- 完整流程迁移建立私有 `app` schema、身份/客户/地址/询价/报价/资金/订单/单据及审计；业务表不暴露给 Data API 的 anonymous/authenticated 直接操作。服务端读取当前成员与员工范围。
- 单独创建受限 runtime DB 角色，避免应用以迁移管理员身份连接；角色密码通过 Secret 配置，不写进 SQL 历史。
- Postgres.js/shared transaction pooler 存在官方提示的 pipelining 风险，先验证 Session pooler 与小连接池及总连接预算；不能把 `prepare:false` 当作完整修复。[官方连接指南](https://supabase.com/docs/guides/database/postgres-js)

## 5 当前接入与运行

已应用 `supabase/migrations/20261004084040_manual_prepaid_flow.sql` 和 `20261004091821_business_fk_indexes.sql`。运行端通过 Session pooler 5432，`max:1`，证书校验使用仓库公开 CA `supabase-ca.crt`。Next 配置将 CA 纳入服务函数文件追踪。迁移连接仅用于本地迁移/隔离集成测试，Vercel 运行环境不要配置迁移管理员密码。

`node scripts/setup-runtime.mjs` 设置受限角色随机密码并写入本地配置（已有运行配置时不重置）。`node scripts/setup-storage.mjs` 建立私有文件 bucket；脚本会校验项目归属。实际数据库密码和密钥不进入迁移、文档或日志。

RLS 对运行角色授权，由服务层独立核对当前账号角色和客户范围；业务表没有对浏览器用户开放直接读写。`session_active` 和 `user_id_for_email` 是固定 search_path 的私有辅助函数，只能由运行角色调用，身份参数分别来自验证后的 JWT 或已通过管理员权限验证的邀请。

本地及生产 Auth Redirect URLs 应分别包含 `APP_ORIGIN/auth/setup` 和 `/auth/confirm`。本轮已检查本地密码恢复链接的回调保持为 `http://127.0.0.1:3000/auth/setup`，并由用户确认管理员邀请及登录成功。生产需配置独立 SMTP、域名和精确回调白名单，关闭公开注册；服务端仍要求数据库中的业务账号才能访问。

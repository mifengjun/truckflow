# 自主注册获客与 shadcn/ui 页面统一设计

日期：2026-10-04
状态：用户于 2026-10-04 要求按此稿继续；实施计划已编写，待计划审阅，尚未实施。

## 1. 目标与范围

用户已选择“注册后询价”，同时要求集成 shadcn/ui。目标是让推广链接的访问者自主成为客户、提交真实询价，由运营人工报价；不再必须由管理员逐个邀请开户。

本次覆盖公开首页、注册/验证/登录、客户资料建立、询价入口，以及现有正式客户门户和后台的组件统一。保留已确认的蓝色视觉、美国 LTL、中文、USD/lb/in、人工报价与预付订单规则。

这不是全系统补齐：退款、追加费、售后、报表、仓库维护、承运商 API 不在本次范围。既有邀请机制继续服务已有客户的同事账号。

## 2. 当前实现与需要改变的地方

- `/` 当前直接跳转 `/login`；没有公开服务介绍页。
- 登录和密码设置已使用 Supabase Auth。注册尚未实现。
- 当前业务会话要求 `app.profiles` 已存在；只有创建 Auth 用户不足以进入系统。
- 客户资料、账户、身份与权限必须由受信服务端建立，不能接受浏览器传来的管理员角色或客户归属。
- 已有询价、人工报价、客户范围隔离和预付订单链路可复用。
- 基础控件已接入 shadcn/ui，但 Sidebar、页面外壳、卡片与部分业务布局仍是自定义 CSS。

## 3. 访问流程

推广链接 → 公开服务页 → 注册 → 验证邮箱 → 补全客户资料 → 创建询价 → 等待人工报价 → 查看报价 → 按现有规则充值、下单。

1. 首页说明服务范围、必要询价资料与人工报价方式，不承诺未经确认的报价时效、价格和客户案例。主入口“注册并询价”，次入口“已有账号登录”。
2. 注册只采集邮箱；邮件验证通过后设置密码及确认密码，再完善客户资料。
3. 发送成功后展示收件邮箱和查收提示，不重复要求输入邮箱；提供倒计时重发、修改邮箱与登录入口。已验证用户继续未完成步骤，已有业务身份的账号进入对应工作区。
4. 邮箱验证后填写公司或业务名称、联系人、联系电话。联系电话兼容大陆和海外，不限制为中国手机号。
5. 完成资料后进入已有询价表单，提交成功进入询价详情，显示“等待人工报价”。询价不要求预存余额。
6. 正常登录返回客户工作区；首次未完成资料的客户进入开户页面。运营账号保持后台入口。
7. 用户可退出后再次登录继续补全资料。验证链接失效、已用、跨设备打开均有明确恢复入口，不无限跳转。

默认沿用既有“下单后人工审核订单”规则；不额外增加尚未确认的客户开户审批。邮箱验证是开放询价的前提，客户冻结仍禁止新业务。

## 4. 路由与身份边界

| 路由 | 访问者 | 行为 |
| --- | --- | --- |
| `/` | 公开 | 服务介绍和注册/登录入口 |
| `/register` | 公开 | 自主注册 |
| `/auth/verify` | 公开 | 验证提示、失败恢复和重发入口，不暴露会话令牌 |
| `/auth/confirm` | 公开回调 | 区分注册确认与邀请/找回密码；成功后各自进入正确流程 |
| `/onboarding` | 已验证但未开户的自主注册账号 | 补全客户资料并建立业务身份 |
| `/login` | 公开 | 登录、注册入口、找回密码 |
| `/portal/*` | 已开户客户 | 询价、报价、订单、地址与资金 |
| `/admin/*` | 有对应权限的员工 | 既有后台业务 |

开户接口使用经验证的 Auth 身份；不以用户可编辑的 `user_metadata` 作为授权依据。注册回调根据服务端记录决定进入密码设置、完善资料或工作区；邀请和找回密码保留各自的密码设置入口。只允许站内固定回跳路径，不接受任意外部 `next` URL。

受邀用户与员工不得通过自主注册覆盖既有资料、创建额外客户归属或获得新权限。不存在业务身份的已验证用户只可访问受限开户能力，不能绕过 `requireActor` 读取业务。

## 5. 客户建立与数据一致性

首次开户在一个数据库事务中：

1. 按 Auth 用户 ID 取得锁并核对邮箱已验证、会话有效。
2. 检查是否已有业务身份；已有则返回原身份，不重复创建。
3. 建立独立 `customers`、零余额 USD `accounts`、客户 `profiles` 和开户审计记录。
4. 角色固定为 `customer_operator`、`customer_finance`，身份固定为 customer，不能由提交参数指定。

每个自主注册主账号先建立独立客户。公司名称相同不代表同一客户，不自动合并、不根据邮箱域名自动加入公司。现有邀请仍由管理员指定客户归属。

客户增加服务端维护的来源信息，用于区分 `self_signup` 与 `admin_created`。推广来源如需保存，仅接收有限长度的来源标识和 UTM 字段，不存整个查询字符串、任意 URL 或浏览器提供的角色。来源字段不能用于授权。

Auth 注册与数据库开户不是跨服务原子事务，因此分为两阶段：未完成开户的 Auth 用户可以重试；事务失败不能留下半套客户/账户/身份。重复提交、并发确认、断线重试都返回同一客户。

## 6. 后台与报价

后台“客户与账号”标明客户来源；“询价与报价”展示新客户的公司和联系人，继续按现有权限处理。

报价发布后，客户在询价详情可查看正式报价。报价邮件通知不以未配置的邮件服务假装成功：本轮先确保站内报价可见；业务报价邮件需要独立的可靠投递和失败重试设计，列为后续工作。注册验证和找回密码邮件属于本轮上线依赖。

没有真实数据时使用 Empty，不能将原型示例混入正式列表。没有实现的模块不添加可点击假入口。

## 7. shadcn/ui 统一范围

继续使用现有 `components.json`、Tailwind v4、Radix 基础和语义主题变量，通过官方 CLI 获取缺少的组件。

| 区域 | 组件与处理 |
| --- | --- |
| 客户/后台外壳 | Sidebar 全组合、移动端收起与展开；替换自定义导航与遮罩 |
| 页面标题 | Breadcrumb、标题和主操作；不添加无效层级链接 |
| 表单与详情分区 | Card 完整组合、Field/FieldGroup、Input、Textarea、Checkbox、NativeSelect；复用业务封装 |
| 登录/注册/开户 | 统一 Card、Field、Alert 和按钮提交反馈；字段级错误与焦点定位 |
| 用户区 | Avatar/Fallback、DropdownMenu，包含现有退出行为 |
| 订单与询价列表 | 保留 shadcn Table、Badge、Pagination、Empty、Skeleton；不声称已实现 TanStack Table 引擎或全量搜索 |
| 提示与确认 | Alert；适合弹窗的危险操作使用 AlertDialog，订单确认保留独立页面 |

颜色、排版和间距由主题与组件 variants 控制；业务组件只负责组合和布局。删除被替换的正式页面 CSS，保留仍依赖的原型样式，避免全局样式覆盖组件状态。

组件替换不得改变真实提交、权限、资金时点或文件授权行为。页面需适配桌面和手机；整页不得横向溢出，表格允许区域内横向滚动。菜单、弹窗、表单支持键盘操作和明确焦点。

## 8. 注册开放条件与邮件

- 使用 Supabase 正常邮箱验证注册，不使用管理员 `createUser` 加 `email_confirm:true` 绕过验证。
- 同源写入检查、输入校验和注册/重发限流必需；角色和客户 ID 不来自公开请求。
- Supabase 的注册开关、验证策略、邮件模板与精确回跳地址需逐项核验，避免只修改前端。
- 正式开放前必须配置真实 SMTP 并验收大陆邮箱收信、链接点击和跨设备验证；现有管理员密码登录不证明邮件投递可用。
- 邮件服务商、发件地址和域名尚未提供。本轮代码和测试可先完成；没有可用邮件配置时不宣传自主注册已可供外部用户使用。
- 验收部署仍使用现有 staging/开发数据库；独立生产环境、备份和大陆网络稳定性继续按架构文档记录。

## 9. 验证与交付标准

- 未验证邮箱不能开户或创建询价；已验证用户开户后只能查看自己的客户数据。
- 并发/重复开户只创建一个客户、一个账户和一个身份；失败可重试。
- 已有管理员、受邀用户及已开户用户的登录、密码设置和公司归属不受影响。
- 注册确认、邀请、找回密码分别回到正确页面；非法/过期链接能恢复，外部回跳被拒绝。
- 两个自主注册客户互不可访问；公开请求无法指定员工角色或别人的客户 ID。
- 新客户完成询价，员工发布报价，客户查看报价；既有预付冻结/扣款/拒单解冻规则回归通过。
- Sidebar 手机切换、表单错误、键盘焦点和空列表通过浏览器验证；构建、类型与 lint 检查通过。
- 测试不发送给真实客户、不改真实管理员密码、不产生真实转账；临时 QA 数据清理。
- 部署后分别记录已验证的在线功能和 SMTP/网络等未完成依赖，不将基础控件接入描述为全系统完成。

### 邮箱优先注册调整（2026-10-04）

注册和重发均使用 Supabase 邮件链接；邮件点击后建立会话，未完成密码设置的客户进入 `/auth/setup?flow=registration`。密码提交成功后进入 `/onboarding`，再次访问注册密码页会继续当前步骤。仅本机保留一小时的 HttpOnly 邮箱 cookie，用于展示收件地址和重发，不参与认证。

Supabase 会为邮件注册生成内部随机密码，不能据此判定用户已设置密码。私有表 `app.registration_passwords` 记录完成状态；Auth 密码在邮箱验证后发生更新时，由私有数据库触发器写入。应用角色只有读取权限，公开客户端无访问权限。迁移兼容原密码优先注册的已有账号。

本轮更新和迁移已在开发环境验证。2026-10-04 已将代码提交 `04ef020` 发布到现有 Vercel 验收环境，部署 `dpl_5Le3TE57dTwbofD1g9xojR5YjFyx`（READY），入口为 https://truckflow-neo.vercel.app/register。线上注册页仅显示邮箱输入框，发送按钮可用；登录、密码设置提示与无效链接页面返回 200，匿名开户状态接口返回 401。应用仍为 staging 并连接现有开发数据库。真实邮件投递未在本轮复测；本地浏览器测试使用一次性验证链接。

# Truckflow 原型评审与开发交接

日期：2026-10-04。范围：全系统页面结构，以及客户询价下单、后台订单处理两个高保真流程。

## 运行与评审

在项目根目录执行 `pnpm install`、`pnpm dev`，打开 `http://127.0.0.1:3000/prototype/index`。默认入口 `/` 跳转客户订单列表。原有三份 HTML 参考稿保留，新的 Next.js 应用从根目录构建；`truck-dispatch/vercel.json` 仅属于旧静态稿。

顶部浅蓝栏属于评审工具，支持角色切换、场景选择和数据重置。订单详情中的角色切换保持同一订单。重置须确认，会清除本浏览器的草稿与新建示例订单。所有数据使用 `truckflow.prototype.v1` 本地存储，不连接 Supabase 或外部系统。

## 页面与需求

`src/modules/prototype/catalog.ts` 是页面入口、需求关联、保真范围和待定规则的唯一清单，页面索引与主导航由它生成。

| 页面 | 需求 | 可操作范围 | 输入及状态 |
| --- | --- | --- | --- |
| G01 页面索引 | 评审工具 | 全部页面入口 | 范围与状态说明 |
| G02–G03 登录、找回 | AUTH | 示例角色入口、反馈结构 | 不输入真实密码、不发送邮件 |
| P01、A01 订单列表 | ORD、TRK | 搜索、状态、日期、分页、详情 | URL 保留条件；空、加载、错误、无权限 |
| P02 新建询价 | INQ、ADR | 收发货→货物服务；草稿自动保存 | 地址必填、数量正整数、重量尺寸为正数；LTL 示例 |
| P03 报价比较 | QUO | 三承运商比较、展开费用、重新询价 | 完整、部分失败、无报价、网络失败、过期 |
| P04 确认下单 | ORD、QUO | 核对快照后创建示例订单 | 未核对禁用、提交锁定、旧版本/过期拒绝 |
| P05、A02 订单详情 | ORD、TRK | 同单跨角色处理、时间线、附件预览 | 待审核、失败、超时待确认、接单；履约状态独立 |
| P06 询价记录 | INQ、QUO | 当前草稿、当前报价入口 | 仅一份草稿；不冒充完整历史记录 |
| P07、A04 地址仓库 | ADR | 列表搜索、新增编辑字段弹层 | 公共仓库/客户私有；仅结构，不保存编辑 |
| P08、A06 资金结算 | FIN | 分栏、记录详情和申请字段结构 | 待核验、到账、失败；无资金动作 |
| P09、A07 服务工单 | CLM | 状态筛选、详情、回复与备注字段 | 待处理、处理中、已完结；不发送、不赔付 |
| A03 客户成员 | CUS、AUTH | 客户状态、成员角色矩阵、邀请结构 | 权限、冻结、邀请规则待定 |
| A05 承运商 | CAR | 服务范围和配置字段 | 待接入；不收集密钥 |
| A08 运营报表 | RPT | 指标和筛选结构 | 固定示例分布，月份不改变数据 |

## 核心验收路径

1. 客户新建询价，清空收货地址并点下一步，确认行内提示及焦点；填入长地址并继续。
2. 添加第二种货物；返回第一步，再进入第二步，确认内容保留。零数量、空重量、负重量不能获取报价。
3. 获取报价，展开费用核对总价。切换部分失败、无报价、网络失败、过期，确认反馈和恢复入口。
4. 默认场景选择报价，在确认页核对实际输入，勾选后提交。提交中按钮禁用；模型按 intentId 去重，保存独立快照。
5. 同一订单切到后台，选择“承运商 · 超时”，核对资料后提交。结果待确认时仅提供核实接单，不再重复创建订单。
6. 核实接单后切回客户，确认状态与追踪号；后台内部备注不出现在客户动态。刷新后检查订单和历史仍在。
7. 列表按订单号、状态和日期筛选，进入详情后返回，确认 URL 条件保留。测试空结果并清除。
8. 打开附件或结构弹层，使用 Escape 关闭，确认焦点回到触发按钮。
9. 390px 查看列表、询价和详情；左侧导航折叠，订单呈卡片，完整地址换行。

## 组件与模块

- `components/ui`：shadcn 风格的 Button、Input 和 Radix Dialog 基础组件；语义按钮、标签、焦点与弹层恢复。
- `components/prototype`：AppShell、ReviewToolbar、FormField、DataTable、AttachmentList；`shared.tsx` 包含 PageHeading、Badge、OrderStatus、AddressSummary、Summary、EmptyState、ScenarioGuard。
- `modules/prototype/model.ts`：种子、类型、报价费用、订单快照、幂等提交、结果转换。整数美分仅用于原型；生产采用架构文档的精确十进制策略。
- `validation.ts`：表单业务校验；`storage.ts`：版本及恢复；`provider.tsx`：共享状态；`mock-adapter.ts`：延迟和异常场景；`order-query.ts`：URL 筛选。
- 页面保持领域调用边界。下一阶段用服务层与 Supabase 替换演示 adapter，不能直接把 localStorage 当作生产数据层。

## 未决规则与限制

需求文档 D01–D13 仍有效。重点包括首发国家/运输方式、成员权限、承运商接入、ERP、预付/月结、账单调整/退款、充值核验、定价有效期、审核和撤单、单据、售后赔付与容量。

演示报价为固定基础费加所选服务，不根据距离、重量、市场价格计价。客户角色和后台角色是视图切换，没有真实认证或安全隔离。数据仅在同一浏览器内共享，不承诺多标签页实时同步。登录、资金、客户、仓库、工单等结构操作不产生业务提交。物流事件不是 GPS；时效不是送达承诺。示例单据不是有效凭证。

开发验证结果和截图在最终验收后补录。Playwright 测试文件作为可复跑资产；当前环境浏览器操作使用 CUA 执行等价路径，不能将其表述为已运行 Playwright 测试。

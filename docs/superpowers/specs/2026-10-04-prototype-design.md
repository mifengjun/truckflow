# Truckflow 交互原型设计

日期：2026-10-04

状态：原型范围与直接制作可点击页面的方式已确认；页面与交互方案待审阅。

## 1 交付目标

交付可在浏览器中审阅的卡派 Web 原型及配套页面说明。原型用于确认布局、交互、字段、组件和异常状态，不承担真实登录、报价、下单和资金业务。

已确认范围：全系统页面结构，加客户询价至订单详情、管理人员处理订单两个核心高保真流程；资金与售后先做结构和状态设计。当前原型作为业务参考，新的设计入口独立保存，所有数据标注为示例。

## 2 界面方向

页面属于操作型产品，视觉优先支持地址阅读、费用比较、状态判断和待办处理。沿用现有原型的侧边导航与内容工作区，把长卡片表单重新组织为任务步骤。统一纯色、线性图标、表格和表单，主操作使用一种强调色。

考虑过三种结构：

| 结构 | 适用场景 | 本次判断 |
| --- | --- | --- |
| 分步询价加右侧摘要；后台列表进入详情工作区 | 客户逐步填写，运营集中处理 | 推荐；让每一步输入和结果有明确边界 |
| 单页长表单加锚点 | 熟练运营反复代客录入 | 保留为未来效率优化，不作为客户主流程 |
| 首页看板加多个功能卡片入口 | 管理者浏览统计 | 看板作为后台二级页，避免挡住实际订单处理 |

推荐交互结构如下。视觉尺寸均为本稿建议，可在原型审阅中调整。

## 4 客户核心流程

### 4.1 询价第一步 收发货

填写提货仓库或外仓地址、收货地址、地址类型、提货日期和运输方式。客户身份固定显示；管理员代客询价时显式显示目标客户。

```text
侧边导航 │ 新建询价                         保存草稿
         │ 收发货 ── 货物与服务 ── 比较报价
         │ ┌────────────────────┬─────────────┐
         │ │ 提货信息           │ 本次运输摘要 │
         │ │ 仓库 / 外仓        │ 起点与终点   │
         │ │ 联系人、完整地址    │ 方式、日期   │
         │ │ 收货信息           │ 资料完成情况 │
         │ │ 地址类型、日期      │             │
         │ └────────────────────┴─────────────┘
         │                           下一步：填写货物
```

完整地址允许换行。公共仓库选项与客户常用地址区分。填写错误后定位字段，输入内容保留。原型示例采用美国 LTL，不代表首发范围确认；FTL/PTL 以待确认服务说明呈现，不生成虚假可用报价。

### 4.2 询价第二步 货物与服务

货物按行新增、删除；每行包含品名、SKU、数量、重量与单位。包装尺寸和托盘数量独立于商品数量。附加服务显示名称、用途与选中状态，费用在正式报价结果中确认。

右侧摘要同步显示路线、提货日期、货物数量、托盘和服务。返回上一步保留输入。离开有改动的草稿需明确处理，不能默默丢失。

### 4.3 报价比较

```text
新建询价 / 比较报价                    修改询价资料
洛杉矶仓 → 收货地址                    LTL · 提货日期
报价结果                             有效期及更新状态
承运商      参考时效    费用明细    总价 USD      操作
承运商 A    2–3 天     展开        385.00       选择报价
承运商 B    3–4 天     展开        412.00       选择报价
承运商 C    暂未返回   重试该报价
```

总价右对齐并使用等宽数字，颜色不暗示最便宜即推荐。费用明细在行内展开；不承诺未经确认的运输时效。需要展示完整结果、部分失败、无报价、请求失败和报价已过期五类状态。

### 4.4 确认与提交

独立确认页面集中显示地址、货物、服务和价格快照，每组可返回对应步骤修改；修改影响价格时提示重新询价。

原型不默认真实扣款，使用“确认提交订单”。提交中按钮显示明确进度并避免重复操作。结果分别展示“订单已创建，等待承运商确认”“承运商已接单”“结果待确认”“提交失败”，每一种结果有对应的下一步。

## 5 订单列表与详情

### 5.1 客户订单列表

页面先显示待处理状态筛选、订单号或追踪号搜索、日期筛选，然后显示订单列表。默认列为订单号、路线、承运商、履约状态、费用、创建时间和详情入口。费用附带币种。

选择状态或搜索词后更新 URL，进入详情再返回保留筛选。空列表引导新建询价，筛选无结果引导清除条件，加载使用保持行高的占位结构。

### 5.2 客户订单详情

```text
返回订单列表
订单 TK…           待提货              联系客服
洛杉矶 → 目的地                         追踪号 / 复制
───────────────────────────────────────────────────
运输进度           订单资料     费用与单据
已创建 → 已接单 → 待提货 → 在途 → 已签收
最新事件 / 地点 / 时间 / 数据更新时间
收发货完整资料                       订单摘要
货物与服务                           总额及报价来源
BOL / 装箱单 / 托盘标签 / POD          附件状态
```

“下单结果”与“履约状态”分开表示；最新事件标明物流当地时区。没有真实 GPS 数据时使用事件时间线，不绘制假位置地图。附件提供已生成、待生成和无权限等状态，不用成功提示替代文件。

## 6 管理后台核心流程

后台默认显示订单工作台，按待审核、提交中、结果待确认、待提货和异常分组。列表加入客户名称与待办原因，不用多排指标卡占据首屏。

订单详情使用主要资料区加右侧操作区：

```text
订单 TK…  / 目标客户                    下单结果、履约状态
┌──────────────────────────┬─────────────────────┐
│ 路线、货物、服务与费用     │ 当前需要处理的事项    │
│ 客户备注与附件           │ 核对资料 / 处理结果   │
│                         │ 备注与主操作          │
├──────────────────────────┴─────────────────────┤
│ 处理记录：时间、人员、动作、原因和结果             │
└────────────────────────────────────────────────┘
```

原型演示资料核对、模拟提交承运商、成功或超时分支，以及确认结果后的状态更新。审核是否必需、人工处理是否可直接改变状态均标注为 D04/D10 待确认假设。

风险操作先说明对象与后果，再确认；普通查看和筛选不弹窗。异常操作记录不能通过刷新丢失，原型数据可通过评审工具重置。

## 7 资金与售后结构页

资金页明确区分可用余额、冻结金额、信用额度、账单和流水。充值显示申请待核验、已到账或失败，不自动改变余额。预付/月结通过原型场景说明展示差异，不据此确定产品策略。

售后列表提供状态、类型、关联订单、更新时间和负责人；详情分客户描述、附件、处理记录和赔付状态。内部备注与对客回复分开表示。工单完结不代表赔付成功。

其他结构页有真实的信息层级和状态说明，但不模拟尚未确认的业务提交结果。

## 8 共享视觉规范建议

| 项目 | 设计基准 |
| --- | --- |
| 页面基础 | 浅色工作区，正文深灰；侧栏与内容层级明确 |
| 主色 | 深蓝 #2454C6，用于主要操作、当前选择和链接 |
| 背景与正文 | 背景 #F5F7FA，内容 #FFFFFF，正文 #182230，次要文字 #526071 |
| 状态 | 成功 #18734A，待处理 #925C0A，错误 #B42318；同时提供文字及图标 |
| 字体 | 中文系统字体优先；不依赖访问 Google Fonts；金额和数量使用 tabular-nums |
| 字号 | 正文 14–16px，辅助 12–13px，页面标题 24px；固定层级，不随视口夸张缩放 |
| 间距 | 4、8、12、16、24、32px；组内紧凑，区块间留白 |
| 控件 | 桌面输入与按钮建议 40px；触控场景至少 44px；一致圆角与焦点样式 |
| 图标 | 同一套线性 SVG 图标，功能由图标加文字共同表达 |
| 动效 | 仅表达展开、提交和状态变化；支持减少动态效果偏好 |

共享组件对应既定技术：DataTable、OrderStatus、AddressSummary、Money、QuoteComparison、FormField、StepNavigation、EmptyState、InlineError、ConfirmDialog 和 AttachmentList。具体 shadcn/ui 封装由后续实现落地，原型先确定行为与视觉契约。

## 9 响应式与可访问性

桌面主评审尺寸 1440px，同时检查 1280px；移动端检查 390px。窄屏侧栏收起，询价变为单列，摘要折叠但可访问；订单列表优先显示订单、状态和路线，详细字段进入详情查看。

地址长文可换行且可查看完整值；移动端操作区不遮挡表单和焦点。语义化按钮、标签和表格，键盘可操作；弹窗打开移动焦点，关闭恢复触发点。文字对比度至少 4.5:1，状态不单靠颜色。

## 10 评审状态与开发交接

原型独立评审工具提供角色切换、场景选择、数据重置和页面索引。业务界面与评审工具明确区分，不把“演示成功/失败”等开发控件混进未来生产页面。

必须可评审：默认、加载、无数据、筛选无结果、字段错误、网络失败、部分报价失败、报价过期、重复提交保护、承运商结果待确认、无权限和长文本。

每个页面记录页面标识、关联需求、主要操作、跳转目标、输入校验、状态和未决规则。交付时附核心流程验收路径、桌面及移动端截图、已知限制和组件映射，后续开发按这些资料落地。

## 11 原型制作与产品实施的边界

本次原型不需要真实 Supabase 项目或承运商密钥，示例记录只供评审。正式认证、数据库、交易和外部接口在后续产品实施阶段接入。原型不得让用户误以为已经真实下单、扣款或发送通知。
